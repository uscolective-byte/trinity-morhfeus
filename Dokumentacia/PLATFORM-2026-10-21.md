# Trinity: ďalší funkčný krok platformy

Základ: main fd20be793862944ad623b53cf4c0a0ad17ad7240 (10.3.0).
Tento krok pridáva skutočné API a nástroj pre doménu hostovaného webu, konfiguráciu OpenAI z existujúceho trezora a úpravy rolí v UI. Nie je to hotová náhrada Cloudflare, Firebase a GitHubu.

## Implementované
- hosting_domain / POST /api/assistant/hosting/domain: site_id, domain, hostname. Iba admin/owner. Vyhľadá existujúci Trinity hosting a zónu, overí účet a stav zóny, odmietne obsadené DNS a pripojí hostname cez Workers Domains API. Zapíše potvrdenie a audit. TLS/HTTP zostávajú pending.
- OpenAI: vybrať overený kľúč a model v Nastaveniach. Žiadny nový API kľúč sa nevytvára ani nezverejňuje. Existujúci Worker Secret zostáva záložným zdrojom.
- Nezávislé čítanie pravidiel a pluginov pri chate prebieha paralelne. Trvanie modelovej odpovede zahŕňa aj prípravu. Žiadne percentuálne zrýchlenie bez merania netvrdíme.
- Používateľ nevidí admin navigáciu Domény a hosting; priame otvorenie hash presmeruje na osobný prehľad. Server naďalej vynucuje oprávnenia.
- Infrastrukturálny stav vypisuje existujúce bindingy s configured/not_checked. Prítomnosť tokenu nie je úspešný živý test.

## Použitie
1. Admin overí existujúci OpenAI kľúč v trezore, vyberie ho v novom formulári, uloží model a spustí živý test.
2. V Studio vytvorí projekt a nasadí ho cez Hosting. ID je viditeľné v zozname.
3. Synchronizuje domény; vloží ID hostingu, doménu zóny a voľný hostname. Napríklad app.example.com pod example.com.
4. Po pripojení overí TLS a dostupnosť webu. Private hosting naďalej vyžaduje Bearer kľúč.

API dokumentácia: https://developers.cloudflare.com/api/resources/workers/subresources/domains/methods/update/

## Ďalšie fázy
- Spoločný projektový manifest: repozitár, staging/produkcia, web, API, D1/R2, domény, audit.
- Provisioning cez Workflows s uloženým stavom každého kroku, opakovaním a návratom zmien.
- Streamovanie odpovedí a meranie času do prvého tokenu; nastavenie rýchleho modelu až po živom benchmarku.
- Izolované používateľské projekty a zdieľanie na základe membership; existujúci primary Studio priestor nie je viacnájomnícka platforma.
- Firebase adaptér rozšíriť nad existujúce publikovanie stavu až po overení účtu a IAM.

## Overenie a limity
Nové testy pokrývajú zónu cudzieho účtu, konflikt DNS, nesprávny suffix, potvrdenie poskytovateľa a zákaz OpenAI project_control. CI má spustiť kompletný build a testy. Živé API, UI a nasadenie sa musia uviesť samostatne podľa skutočných výsledkov. Predchádzajúci development deploy blokovala kontrola /health na auru.dev (HTML namiesto JSON); tento krok kontrolu neobchádza.
